# 变电站逐小时电量质检系统

面向变电站数据员 → 结算组交接场景的网页应用：

- 管理进/出线计量点配置；
- 手工录入逐小时电量（带修订号）；
- **导入网关累计抄码 CSV**，自动对相邻整点作差得到小时电量，并可逐条追溯到原始 CSV 行；
- 按日期与容差生成质检日报；追溯变更时旧日报自动失效，日报与其依据快照始终来自
  同一已提交状态。

## 技术栈

- FastAPI（Python 3.11）+ SQLite（WAL 模式）
- 原生 HTML/CSS/JS 单页（无构建步骤）
- Docker Compose 一键启动，数据持久化在命名卷 `substation-data`

## 启动方式

```bash
docker compose up --build -d
# 浏览器打开
http://localhost:8000/
# OpenAPI 交互文档
http://localhost:8000/docs
```

停止：`docker compose down`（数据保留在卷中；`docker compose down -v` 同时清除数据）。

演示两个实例并发补传/重试：

```bash
docker compose --profile ha up --build -d
# 主实例 :8000，第二实例 :8001，共享同一数据卷与 SQLite 单写锁
```

本地无 Docker 时可直接运行（需 Python 3.11 并 `pip install -r requirements.txt`）：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 业务规则与设计说明

### 1. 计量点配置（`POST /api/configs`，整版提交）

- 按**生效 UTC 小时整点**提交，一次提交即该生效小时的完整配置（全量语义）。
- 每个计量点在同一版本中只能出现一次：**同点不得兼任进线与出线**，且进、出线至少各一个。
- 同一生效小时重复提交：内容完全相同则幂等忽略；内容不同则**同版异文拒收**
  （HTTP 400），需用新的生效小时整版提交。
- 某小时的“当时配置”= `effective_hour <= 该小时` 中最新的一版。

### 2. 逐小时电量（`POST /api/readings`）

- 按 `(计量点, 小时)` 维护修订号，**必须从 1 开始严格 +1 递增**：旧修订号、跳号拒收。
- 电量必须为有限非负数（NaN/Infinity、负数拒收）。
- 同修订号重复提交：内容相同幂等忽略；内容不同**同版异文拒收**。
- 一个请求内同一 `(计量点, 小时)` 不允许出现两次。
- 整批在**单个事务**内处理，任何一条拒收则整批回滚，不存在部分写入。
- 手工录入与 CSV 派生读数**共用同一修订序列**：更正派生小时的手工读数会自动成为下一个修订号。

### 3. 累计抄码 CSV 导入（`POST /api/imports`，multipart 上传 `file`）

输入列：**计量点、UTC 整点、非负累计电量（kWh）**，最多 **500 行**。

- 有表头时按列名映射（列顺序任意、允许额外说明列），支持
  `point_id,hour,cumulative_kwh`、`计量点,整点,累计电量` 等中英文别名；
  无表头时按前三列固定顺序解析。
- 时间接受常见网关写法（`2026-11-15T08:00:00Z`、`2026-11-15 08:00:00`、
  `2026-11-15T08:00Z`、`+00:00`），但**必须落在 UTC 整点**；带非零时区偏移或
  非整点一律拒收。
- 同一文件内同点同刻**示数不同** → 整批拒收；同值重复行保留在批次原文里。
- 同一文件重传（SHA-256 相同）→ **幂等**，返回首次批次，不新增示数/派生/失效。
- 补传可与库内示数配对：同一 `(计量点, 整点)` 已在库且值相同 → 保留**首次来源**
  （批次 + 行号）；值不同 → **整批拒收**。
- 派生规则：**仅相邻整点作差**，差值 `end − start` 计入**起始小时**；
  缺少任一端点则不生成。差值**为负** → 整批拒收。
- 派生读数即正式小时电量，因此与手工读数一样要求计量点**已在某版已提交配置中登记**；
  未登记点的派生 → 整批拒收（示数端点也一并回滚）。
- 同值重传保留首次来源；某派生小时**已有人工读数** → 整批拒收。
- 派生读数与人工读数一样参与日报质检。

### 4. 原件存储与 SHA-256 核验下载

- 原始 CSV 按**字节**保存为 `data/originals/<sha256>.csv`（内容寻址，天然去重）。
- 写入顺序：临时文件 → `fsync` → 同目录原子 `rename` → `fsync` 目录 → 才提交数据库
  事务。崩溃只可能留下未引用的孤儿文件，**不可能出现库内有可用读数而原件缺失**。
- `GET /api/imports/{id}/download` 先重算 SHA-256，只有与入库值一致才返回字节
  （响应头 `X-Content-SHA256`，附件名保留原始文件名）；原件缺失或被篡改返回 500，
  绝不返回未核验内容。
- `GET /api/imports/{id}/verify` 返回重算摘要供人工核对。
- 启动时默认核验**全部**被引用原件（`SUBSTATION_VERIFY_ORIGINALS_ON_START=0` 可关闭），
  任一缺失/损坏即**拒绝启动**，避免带着坏数据对外服务；同时清理超过 1 小时的
  孤儿文件与临时分片（年龄保护避免误删并发实例正在提交的上传）。

### 5. 追溯查询

- `GET /api/imports`：批次列表（文件名、字节数、行数、SHA-256、派生条数）。
- `GET /api/imports/{id}`：批次每一物理数据行（含 CSV **行号**）与相关派生读数，
  每个派生修订列出**两端示数、各自来源批次与行号**。
- `GET /api/readings`：每条读数带 `source`（manual/derived）与两端示数追溯字段；
  `basis` 文本同时写入日报依据，因此历史日报也能追到原始 CSV 行。
- 网页“累计抄码导入”页可上传、下载示例模板、查看批次行与派生追溯、下载/核验原件。

### 6. 质检日报（`POST /api/reports/generate`）

输入日期（UTC 自然日）与容差，对 24 个小时逐小时判定：

1. 该小时无生效配置 → **不完整**；
2. 有配置但任一计量点缺读数 → **不完整**，列出缺失计量点；
3. 数据齐全：计算 `进线合计 − 出线合计`，**绝对差严格大于容差**才标**异常**
   （等于容差不算异常）；否则正常。

日报状态：任一小时不完整则整体 `incomplete`；否则任一小时异常则 `anomaly`；
全部正常为 `complete`。每小时都记录：当时配置版本、每个计量点的读数、修订号、
来源（人工/派生）、提交时刻与派生依据、差值核算。日报还保存完整的配置/读数
**JSON 快照**，因此历史报告的依据永不随后续录入而改变。

### 7. 追溯变更与旧日报失效

- 更正读数（手工或派生新修订）：该读数对应小时所在 UTC 自然日的**仍有效日报全部失效**，
  其他日期不受影响。
- CSV 导入派生/更正读数的失效动作与导入事务**同一事务提交**；被整批拒收的导入
  不会失效任何日报。
- 提交新生效小时的配置（含向过去补录）：生效日**当日及以后**日期的仍有效日报失效。
- 失效日报保留可查（带失效原因与时间戳），但不再视为有效；重新生成得到新日报。

### 8. 并发与“半批/半份”防护

- 所有写操作使用 `BEGIN IMMEDIATE`，SQLite 单写锁使上传/生成/配置变更串行化；
  `busy_timeout` 30 秒，两个实例共享同一数据卷时同样安全。
- 导入的批次、行原文、示数、派生读数、日报失效在**一个事务**内提交：任一条拒收
  即整批回滚，不存在半批示数或半批派生。
- 上传先落盘再开事务，所以“已提交读数缺原件”不可能出现；事务失败留下的文件是
  未被引用的孤儿，启动时安全清理。
- 同一文件并发重放（两个实例同时上传同一 SHA-256）：一个成功创建批次，其余返回
  `duplicate_ignored`，不会重复派生或重复失效。
- 日报生成在一个事务内完成全部快照读取与落库；同日期同容差重复生成返回同一份
  有效日报（幂等），不同容差是不同日报。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/configs` | 整版提交配置 |
| GET | `/api/configs` | 配置版本列表 |
| POST | `/api/readings` | 批量录入手工读数 |
| GET | `/api/readings?point_id=&hour=` | 读数查询（含来源与追溯） |
| POST | `/api/imports` | 上传累计抄码 CSV（multipart `file`） |
| GET | `/api/imports` | 导入批次列表 |
| GET | `/api/imports/{id}` | 批次原文行（含行号）与派生追溯 |
| GET | `/api/imports/{id}/verify` | 重算原件 SHA-256 |
| GET | `/api/imports/{id}/download` | 核验后下载原件 |
| POST | `/api/reports/generate` | 生成/幂等取回日报 |
| GET | `/api/reports?report_date=&include_invalid=` | 日报列表 |
| GET | `/api/reports/{id}` | 单份日报（含快照依据） |
| GET | `/healthz` | 健康检查 |

业务拒收统一返回 `400 {"error": "..."}`；请求体格式错误返回 422；
原件缺失/篡改返回 `500 {"error": "..."}`。

## 数据模型（SQLite）

- `config_version` / `config_point`：配置版本与版本内计量点（角色 incoming/outgoing）。
- `reading`：主键 `(point_id, hour, revision)`，含规范化提交文本、提交时刻；
  `source` 区分 `manual`/`derived`，派生行记录两端示数、来源批次与 CSV 行号。
- `import_batch`：CSV 批次（SHA-256 唯一、原始文件名、字节数、行数、导入时刻）。
- `import_row`：批次内每一物理数据行原文与行号（保留同批同值重复行）。
- `meter_reading`：库内累计示数，主键 `(point_id, hour)`，值一旦落库不可改写；
  记录首次来源批次与行号。
- `report`：日报结论 + `config_snapshot`/`reading_snapshot` 快照 JSON；
  `invalidated_at` 非空即失效。
- 旧库启动时自动补齐 `reading` 的派生来源列（向前兼容）。
